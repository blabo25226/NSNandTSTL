## 1. 目的とスコープ



### 1.1 目的

論文の実験プロトコルをソフトウェアで再現し、次を達成する。

1. **層寄与プロファイル**（全 Transformer 層の `C(k)`、深さ正規化プロット）
2. **単層学習が Full GRPO に匹敵・上回る**現象の確認（少なくとも 1 モデル）
3. **§4 戦略**（Boost Bk / Only Bk / Mid-k）が Full を上回る傾向の確認
4. （R2+）クロスデータセット Spearman 相関、（R3）複数モデル・アルゴリズム



### 1.2 再現レベル定義


| レベル     | 名称         | 論文対応              | 完了の目安                                           |
| ------- | ---------- | ----------------- | ----------------------------------------------- |
| **0-B** | MLP 縮小     | 手順のみ              | ✅ 完了                                            |
| **R1**  | Mini-LLM   | §2–3 の骨格          | GPT-2/Qwen2.5-0.5B 級、数学プロンプト小規模、層スキャン 全層        |

| **R4**  | 完全         | §3.4 + §4 + §5 全て | 7 モデル、GiGPO/Dr.GRPO、ALFWorld、投票解析（**任意・研究外注**）  |

## 2. 論文実験プロトコル（再現対象の整理）



### 2.1 層寄与（変更なし）

```
C(k) = (S_k - S_base) / (S_full - S_base)
```

- `S`: in-domain ベンチマーク平均スコア（論文 §3.1）。数学なら 4 ベンチ平均等。
- 単層学習: Transformer 層 `θ_k` のみ更新。`θ_emb`, `θ_head` は **常に学習可**（論文 §2.2 実装注記）。



### 2.2 公平比較プロトコル（論文 §3.1）

1. Full-parameter GRPO の学習率をチューニング → 最良を `S_full` の基準に
2. **同じ学習率**を全単層 run に適用
3. バッチサイズ・KL・clip・ステップ数は Full と単層で同一
4. 単層が Full を上回る場合のみ「再現成功」とみなす（Full が弱い設定は不可）



### 2.3 Primary 実験（R2/R3 の核）


| 項目            | 論文設定                                   |
| ------------- | -------------------------------------- |
| モデル           | Qwen3-1.7B/4B/8B-**Base**              |
| データ           | NuminaMath-CoT                         |
| アルゴリズム        | GRPO                                   |
| 層スキャン         | 全層（28 or 36）独立学習                       |
| 評価（in-domain） | MATH500, GSM8K, OlympiadBench, AMC の平均 |




### 2.4 §4 戦略（R2 から実装）


| 戦略       | 論文設定（Qwen3）                         |
| -------- | ----------------------------------- |
| Boost Bk | 上位 k 層 lr = 1e-5、他 = 5e-6（2×）       |
| Only Bk  | 上位 k 層のみ学習                          |
| Mid-k    | 位置 `[⌊L/2−k/2⌋, ⌊L/2+k/2⌋)` の k 層のみ |




### 2.5 汎化実験（R3）

- Qwen3-1.7B: DeepScaleR / DeepCoder で層ランキング相関（Spearman）
- Qwen2.5-Math-1.5B + Dr. GRPO（R3 後半）
- 重み変化量 `‖Δθ_k‖` vs `C(k)` プロット（§5）

### Phase R1: Mini-LLM 手順検証（必須・ローカル可）

| Step | 内容                                                                            | 成果物                         |
| ---- | ----------------------------------------------------------------------------- | --------------------------- |
| R1-1 | `llm_freeze.py`: `named_transformer_layers(model)`、`freeze_all_except_layers` | テスト: 層 k のみ `requires_grad` |

## 7. 設計判断（要承諾）


| #   | 判断                                               | 理由                        |
| --- | ------------------------------------------------ | ------------------------- |
| 1   | **GRPO 実装は TRL を第一選択**（`trl.GRPOTrainer`）        | 依存が軽い。R2 で不足なら veRL を検討   |
| 2   | **層の単位 =** `model.model.layers[i]`（Qwen/Llama 系） | 論文の Transformer block に対応 |
| 3   | **emb + lm_head は常に学習可**                         | 論文の単層学習実装注記に合わせる          |
| 4   | **チェックポイント**: 各 run ごとに `results/.../layer_k/`   | 28 層スキャンの再開可能に            |
| 5   | **R2 データはサブセットから開始**                             | 全データは R3。再現性はプロトコル優先      |
| 6   | **評価は** `lm-eval-harness` **または軽量自前**            | 4 ベンチは R2、12 ベンチは R3      |
| 7   | **数値一致は追求しない**                                   | プロファイル形状と戦略順位を主指標         |
